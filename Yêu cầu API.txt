
A. CRUD cơ bản cho JobPosition (phía "nhiều")

1. GET /api/v1/job-positions — danh sách vị trí công việc, nên hỗ trợ filter theo educationLevelId và từ khoá tên.
2. GET /api/v1/job-positions/{id} — chi tiết 1 vị trí, trả kèm thông tin trình độ học vấn tối thiểu (EducationLevelId, EducationLevelName).
3. POST /api/v1/job-positions — tạo mới, body (JobPositionMeta) có EducationLevelId. Bắt buộc validate: EducationLevelId phải tồn tại và IsDeleted = false.
4. PUT /api/v1/job-positions/{id} — cập nhật (đổi tên, đổi yêu cầu học vấn tối thiểu...), validate FK như trên.
5. DELETE /api/v1/job-positions/{id} — xoá mềm.

B. API khai thác trực tiếp mối quan hệ 1-N (trọng tâm câu hỏi)

6. GET /api/v1/education-levels/{id}/job-positions — lấy tất cả vị trí công việc đang yêu cầu tối thiểu trình độ học vấn này (truy vấn từ phía "1" xuống "nhiều"). Có thể làm song song bằng query param GET /api/v1/job-positions?educationLevelId={id} nếu muốn gộp vào API list ở mục A.1.
7. GET /api/v1/education-levels/dropdown (hoặc /lookup) — danh sách rút gọn chỉ gồm Id, Name, dùng để đổ combobox khi tạo/sửa JobPosition ở FE, tránh gọi API list đầy đủ.

C. API/logic đảm bảo toàn vẹn dữ liệu

8. Bổ sung kiểm tra ràng buộc khi xoá EducationLevel: DELETE /api/v1/education-levels/{id} hiện tại chưa check gì — cần thêm logic "nếu còn JobPosition nào (chưa xoá) đang tham chiếu tới EducationLevel này thì từ chối xoá" (trả Code = -1, HTTP 400) để tránh orphan reference.
9. Có thể tách riêng GET /api/v1/education-levels/{id}/usage-count để FE kiểm tra trước khi cho phép người dùng bấm xoá (hiển thị cảnh báo "đang có N vị trí sử dụng").

D. (Tuỳ chọn) API thống kê

10. GET /api/v1/education-levels/statistics — đếm số lượng JobPosition theo từng EducationLevel, phục vụ dashboard/báo cáo.

Về tầng dữ liệu cần bổ sung tương ứng

- Bảng JobPosition trong 01_Tables.sql cần thêm cột FK: EducationLevelId UNIQUEIDENTIFIER NOT NULL với CONSTRAINT FK_JobPosition_EducationLevel FOREIGN KEY (EducationLevelId) REFERENCES EducationLevel(Id).
- Cần tạo đủ bộ file theo đúng pattern hiện có của EducationLevel: JobPositionMeta, JobPositionViewModel, IJobPositionRepository/JobPositionRepository, IJobPositionService/JobPositionService, và điền code thật vào JobPositionController (hiện đang rỗng tại DemoApi/Api/Controller/JobPositionController.cs — thực ra file này chưa tồn tại, chỉ có DemoApi/Domain/Models/JobPosition.cs là class rỗng).

CREATE OR ALTER PROCEDURE [dbo].[spApp_SelectByCompany]
    @TenantId  NVARCHAR(50),
    @CompanyId NVARCHAR(50)
AS
BEGIN
    SET NOCOUNT ON;
    SELECT a.[Id], a.[Code], a.[Name], a.[Description], a.[Category], a.[IconUrl], a.[Url], a.[Status], a.[SortOrder], a.[IsDefault],
           (SELECT COUNT(DISTINCT ua.[UserId]) FROM [dbo].[AppUserAccess] ua
            WHERE ua.[AppId] = a.[Id] AND ua.[TenantId] = @TenantId AND ua.[CompanyId] = @CompanyId AND ua.[IsDelete] = 0) AS [UserCount]
    FROM [dbo].[Companys] c
    CROSS APPLY OPENJSON(ISNULL(c.[AppIds], N'[]')) j
    INNER JOIN [dbo].[App] a ON a.[Id] = j.[value]
    WHERE c.[Id] = @CompanyId AND c.[TenantId] = @TenantId
    ORDER BY a.[SortOrder] ASC, a.[Name] ASC;
END
GO
